## iblog 个人博客项目初始化

搭建了一套前后端分离的个人博客骨架（monorepo，目录 `D:/develop/IdeaProjects/iblog`）。

### 技术选型（用户确认）

- 后端：Java 17 + Spring Boot 3.3.4 + MyBatis-Plus 3.5.7 + MySQL 8 + Redis + JWT(jjwt 0.12.6) + springdoc
- 管理后台：Vue3 + Vite5 + TS + Element Plus 2.8 + Pinia + Vue Router + axios
- 官网前台：Vue3 + Vite SPA + marked（用户明确选择 SPA，已知 SEO 弱，README 中标注了预渲染/Nuxt 升级路径）
- 部署：Docker Compose（mysql + redis + iblog-server + iblog-admin + iblog-web），Nginx 反代 /api
- 用户明确：不需要适配移动端

### 关键实现约定

- 统一响应体 `R<T>`：code/msg/data，200 成功、401 未登录、400 业务参数错、500 异常
- 鉴权：JWT 签名 + Redis 存 `iblog:login:token:{userId}`，实现可主动注销；拦截 `/api/admin/**`，放行 `/api/admin/auth/login`
- 管理员账号 admin/admin123 由 `DataInitializer`（ApplicationRunner）在首次启动时用 BCrypt 生成，避免在 SQL 里写死密文
- 逻辑删除：全表 `deleted` 字段 + MyBatis-Plus 全局 logic-delete-field
- 站点配置走 Redis 缓存（key `iblog:site:config`，2 小时），保存时主动失效
- 接口分两域：`/api/admin/**`（需登录）、`/api/portal/**`（公开）
- 表前缀：`sys_user`、`blog_article`、`blog_category`、`blog_tag`、`blog_article_tag`、`blog_comment`、`blog_site_config`
- 文章列表查询用 `LambdaQueryWrapper.select(...)` 排除 content 字段，减小报文

### 校验结果

- 后端：`mvn compile` 通过（本机用 portable Maven 3.9.9 + JDK 21，release 17）
- 环境注意：本机原先没有 Maven，已下载到 `C:\Users\Administrator\.workbuddy\tools\apache-maven-3.9.9`
- 前端：见当日构建验证

- 图片上传到 OSS

## 后端构建迁移 Maven → Gradle

按要求把 `iblog-server` 的依赖管理从 Maven 换成 Gradle。

### 改动清单

- 删除 `pom.xml`、`target/`
- 新增 `settings.gradle`、`build.gradle`（Groovy DSL）、`gradle.properties`
- 新增 Gradle Wrapper：`gradlew` / `gradlew.bat` / `gradle/wrapper/*`（版本 8.10.2）
- 新增 `.dockerignore`
- `Dockerfile` 构建阶段改为 `eclipse-temurin:17-jdk` + `./gradlew bootJar`，产物路径 `build/libs/iblog-server.jar`
- `.gitignore`（根 + 模块）改为 Gradle 规则；**根 .gitignore 的 `*.jar` 必须加 `!gradle/wrapper/gradle-wrapper.jar` 例外**
- `README.md` / `deploy/DEPLOY.md` 同步命令与说明

### Gradle 配置要点

- 插件：`java` + `org.springframework.boot 3.3.4` + `io.spring.dependency-management 1.1.6`
- 用 `sourceCompatibility/targetCompatibility = 17` 而非 toolchain —— 这样只有 JDK 21 的机器也能编译（toolchain 会强制要求装 JDK 17）
- 显式加 `options.compilerArgs << '-parameters'`，避免 Spring Boot 3.2+ 的 `@RequestParam` 参数名推导问题
- `bootJar { archiveFileName = 'iblog-server.jar' }` 固定产物名，方便 Dockerfile 引用
- 仓库：阿里云镜像优先 + mavenCentral 兜底

### 本机环境坑（重要）

- 本机 `GRADLE_USER_HOME=D:\develop\gradle_user_home`，全局 `init.gradle` 把 maven central 重定向到内网 Nexus `http://192.168.0.244:8081/repository/maven-public/`
- 该目录下的 `caches/journal-1/journal-1.lock` 被常驻 Gradle 守护进程占用，直接跑会报 `拒绝访问` → 验证时改用独立目录 `C:\Users\Administrator\.workbuddy\tools\gradle-home`
- 本机已装便携 Gradle `C:\Users\Administrator\.workbuddy\tools\gradle-8.10.2`，JDK 为 Zulu 21
- services.gradle.org 下载很慢（134MB 约 12 分钟），wrapper 里已注释腾讯云/阿里云镜像备选

### 校验结果

- `./gradlew clean bootJar -x test` → BUILD SUCCESSFUL，产物 `build/libs/iblog-server.jar`（43MB）
- 顺带修掉 `RedisConfig` 里 `Jackson2JsonRedisSerializer#setObjectMapper` 的过时 API 警告，改用 `new Jackson2JsonRedisSerializer<>(mapper, Object.class)`

## 依赖源改造：彻底避开公司内网 Nexus

用户要求依赖不能走公司内网，可以使用阿里云镜像。

### 背景

本机 `GRADLE_USER_HOME=D:\develop\gradle_user_home` 下的全局 `init.gradle` 会：
1. 把 `https://repo1.maven.org/maven2` 从所有项目中移除
2. 无条件追加内网 Nexus `http://192.168.0.244:8081/repository/maven-public/`

这会导致离开公司内网就无法构建。

### 解决方案

- `build.gradle` 中显式 `repositories.clear()` 再重建仓库列表 —— 这会清掉 init.gradle 通过
  `allprojects { repositories { ... } }` 注入的仓库（init 在项目创建时执行，早于 build.gradle 求值）
- `settings.gradle` 增加 `pluginManagement { repositories { ... } }`，插件也走阿里云
- `gradle-wrapper.properties` 的 distributionUrl 换成阿里云 Gradle 镜像

### 最终生效的仓库

| 类型 | 地址 |
| --- | --- |
| Gradle 发行包 | `https://mirrors.aliyun.com/macports/distfiles/gradle/gradle-8.10.2-bin.zip` |
| Maven 依赖 | `https://maven.aliyun.com/repository/public` |
| 依赖兜底 | `https://repo.maven.apache.org/maven2/`（公网，可删） |
| Gradle 插件 | `https://maven.aliyun.com/repository/gradle-plugin` + `plugins.gradle.org/m2` |
| npm（未改动，本已合规） | `https://registry.npmmirror.com` |

### 验证方法（可复用）

把内网 `init.gradle` 复制到测试用 GRADLE_USER_HOME，再用临时 init script 打印仓库：
`C:\Users\Administrator\.workbuddy\tools\verify-repos.gradle`（内容：settingsEvaluated 打印
pluginManagement 仓库 + projectsEvaluated 打印各项目仓库）。
验证结果：仓库列表中无 `192.168.0.244`，构建 SUCCESSFUL。

### 经验

- 阿里云的 `mirrors.aliyun.com/macports/distfiles/gradle` 路径**并不比官方源快**，
  本机实测都是 ~180KB/s（134MB 约 12 分钟），瓶颈更像本机出口带宽而非镜像
- 用 `repositories.clear()` 剥离机器级注入的仓库，是让单个项目摆脱公司私服的有效手段

## 修复 IDEA 不识别为 Java 项目

现象：`IblogApplication.java` 没有运行/编译按钮。

### 根因

`.idea/` 里是**手工创建的普通模块**，不是 Gradle 工程：

- `.idea/iblog.iml` 是 `type="JAVA_MODULE"`，`<content url="file://$MODULE_DIR$" />` 里
  **没有任何 sourceFolder** → `src/main/java` 没被标记为源码根
- `.idea/modules.xml` 只登记了这个 .iml，**没有 Gradle 关联**（无 `.idea/gradle.xml`）
- 仓库根目录原本没有任何 Gradle 构建文件，IDEA 打开根目录时无从识别

### 解决

把仓库根目录改造成**聚合 Gradle 工程**（保留 iblog-server 的独立可构建性）：

- 根 `settings.gradle`：`rootProject.name = 'iblog'` + `include 'iblog-server'` + pluginManagement 阿里云镜像
- 根 `build.gradle`：只做 `allprojects { group/version }`，并注释常用命令
- 根目录补 `gradlew` / `gradlew.bat` / `gradle/wrapper/*`（与 iblog-server 各一份）
- 删除 `.idea/iblog.iml` 和 `.idea/modules.xml`（错误的普通模块定义）
- 新增 `.idea/gradle.xml`（`linkedExternalProjectsSettings` 指向 `$PROJECT_DIR$`，distributionType=DEFAULT_WRAPPED）
- 新增根 `.dockerignore`，README 增加「在 IDEA 中打开」章节

### 关键结论

- `iblog-server/settings.gradle` **必须保留**：它让 `cd iblog-server && ./gradlew bootJar`
  以及 Docker 构建（context 为 iblog-server）继续可用；从根目录构建时它会被正常忽略，不冲突
- 两个入口都实测通过：根目录 `:iblog-server:bootJar` ✅、子目录 `./gradlew bootJar` ✅
- Git 忽略规则要点：根 .gitignore 的 `*.jar` 必须配 `!gradle/wrapper/gradle-wrapper.jar`，
  否则 wrapper jar 提交不上去；已验证两个位置的 jar 都未被忽略

## iblog-admin 改用 pnpm

### 改动清单

- 删除 `package-lock.json` 与 npm 生成的 `node_modules`，新增 `pnpm-lock.yaml`（lockfileVersion 9.0）
- `package.json` 增加 `"packageManager": "pnpm@11.5.0"`
- 新增 `iblog-admin/.npmrc`：固定 `registry=https://registry.npmmirror.com`（延续“不走内网”的约定）
- 新增 `iblog-admin/pnpm-workspace.yaml`：声明 `allowBuilds`
- 新增 `iblog-admin/.dockerignore` 和 `iblog-web/.dockerignore`（**修掉一个潜在 bug**：原 Dockerfile
  的 `COPY . .` 会把宿主机的 `node_modules` 覆盖进镜像）
- `Dockerfile` 改为 `npm i -g pnpm@11.5.0` + `pnpm install --frozen-lockfile` + `pnpm build`
- 根 `.gitignore` 增加 `.pnpm-store/`
- README / DEPLOY.md 同步

### pnpm 11 的两个坑（重要）

1. **pnpm 11 不再读取 package.json 的 `pnpm` 字段**，配置必须写在 `pnpm-workspace.yaml`。
   写错位置只会给 WARN，不生效。
2. **字段名是 `allowBuilds`（map 结构），不是 pnpm 10 的 `onlyBuiltDependencies`（数组）**：
   ```yaml
   allowBuilds:
     esbuild: true
     vue-demi: true
   ```
   pnpm 会自动生成一个带 `set this to true or false` 占位值的模板文件。
   不批准的话，`pnpm build` 会在 `runDepsStatusCheck` 阶段直接 exit 1，
   报 `ERR_PNPM_IGNORED_BUILDS`，看起来像是构建挂了其实是依赖状态检查。

### 校验结果

- `pnpm install` → 成功，esbuild / vue-demi 的 postinstall 均执行成功
- `pnpm build` → ✅ built in 9.15s，产物与 npm 版一致
- `pnpm type-check` → ✅ 零错误
- iblog-web 仍使用 npm，未改动
